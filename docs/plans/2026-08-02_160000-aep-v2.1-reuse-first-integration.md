# AEP v2.1 Reuse-First Integration Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Implement only AEP v2.1 controls not already solved by maintained external skills/tools; integrate existing work behind optional adapters, preserve `agentic-loop` core as portable Bash + `git` + `jq`, and leave auditable evidence for Discovery, Conventions, Complexity, Decisions, and Unverified Claims.

**Architecture:** Keep `agentic-loop` responsible for mechanical, repository-local gates: artifact contracts, scope, worktree lifecycle, secret safety, explicit task records, and exit-code semantics. Install/refer to external skills for reasoning workflows rather than copying their prose. Use optional adapters for semantic discovery (Serena) and complexity (Lizard); the core must degrade honestly to `UNKNOWN` or a declared manual review requirement, never simulate a semantic check with a shallow grep and call it equivalent.

**Tech Stack:** Existing Bash 3.2-compatible CLI (`bin/al`, `core/cmd/`, `core/lib/`), `git`, `jq`, current test harness (`tests/run.sh`), GitHub Actions, external optional tools `serena-agent` / LSP and `lizard`, Markdown Agent Skills (`SKILL.md`).

---

## Non-negotiable design decisions

1. Do not copy external skill bodies into this repository.
   - Install or link upstream skills using documented upstream install mechanisms.
   - Local wrapper skills may state when to invoke an upstream skill and what artifact `agentic-loop` requires afterward, but must not fork/rewrite their content.

2. `agentic-loop` core stays dependency-light.
   - Required: Bash, git, jq.
   - Optional: Serena and Lizard.
   - Missing optional tool must produce a precise state (`UNKNOWN` / manual-review-required), not a fake PASS.

3. Mechanically enforce only facts a tool can actually observe.
   - Require a Discovery record; do not claim this proves no reusable code exists.
   - Require a Decision record for declared significant decisions; do not infer significance from keyword heuristics alone.
   - Use Lizard’s measured CCN; do not write a custom language parser.
   - Treat convention checks generated from static code scans as candidates until owner approval marks them hard constraints.

4. `AGENTS.md` remains a pointer and stays under its instruction budget. Detailed policy belongs in `WORKFLOW.md`, `CONVENTIONS.md`, role skills, and task artifacts.

5. GitHub Issue/PR state remains source of workflow truth. Local `.agent/` files are task/evidence artifacts and must contain task/PR references where available.

## Risks and tradeoffs

| Risk | Mitigation |
|---|---|
| Turning five gates into bureaucracy | All AEP gates are opt-in per task/project; Metrics decides whether overhead pays for itself after 2–4 weeks. |
| Serena/LSP setup cost on small repo | Optional adapter; documented command fallback has lower confidence and is labeled as such. |
| Lizard thresholds punish fluent Laravel code | Candidate/approved complexity config; exceptions have owner, expiry, and reason; no global hardcoded “15”. |
| Discovery becomes checkbox theater | Require concrete commands, inspected paths, dependency check, conclusion, confidence class, and independent reviewer check. |
| Generated conventions hallucinate architecture | Scanner records observable signals only; owner must approve machine-facing hard constraints. |
| “Popularity bias” regex creates false positives | Decision verifier validates evidence/candidate structure; only flags popularity when it is sole stated decision/rejection reason. |
| Claim scanner declares prose false | It never does; it requests independent review, and only unresolved structured claims block readiness. |
| Vendoring third-party skill content causes drift | Upstream integrations stay pinned external dependencies; local wrappers contain only artifact/enforcement links. |
